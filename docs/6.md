# Backup & Disaster Recovery

## 1. Instalasi Restic dan Backrest

Restic adalah mesin pencadangan yang dipasang dari repositori resmi Ubuntu. Backrest adalah antarmuka web untuk mengelola Restic, diinstal dari rilis resmi GitHub.

```bash
sudo apt update
sudo apt install -y restic

# Unduh arsip biner Backrest untuk Linux AMD64
curl -fLo /tmp/backrest_Linux_x86_64.tar.gz \
  https://github.com/garethgeorge/backrest/releases/latest/download/backrest_Linux_x86_64.tar.gz

# Ekstrak ke direktori sementara
mkdir -p /tmp/backrest-install
tar -xzvf /tmp/backrest_Linux_x86_64.tar.gz -C /tmp/backrest-install

# Jalankan skrip instalasi
cd /tmp/backrest-install
sudo ./install.sh
```

Jika `install.sh` tidak dapat dieksekusi, beri izin terlebih dahulu:

```bash
chmod +x install.sh
sudo ./install.sh
```

## 2. Konfigurasi Layanan Systemd Backrest

Skrip instalasi otomatis membuat unit `backrest.service` dengan pengguna biasa dan akses jaringan terbatas pada localhost. Agar Backrest dapat membaca direktori data Forgejo (`/var/lib/forgejo`) dan dasbor webnya dapat diakses dari luar, ubah unit tersebut.

Buka berkas unit layanan:

```bash
sudo nano /etc/systemd/system/backrest.service
```

Pastikan isinya seperti berikut:

```ini
[Unit]
Description=Backrest
After=network.target

[Service]
Type=simple
User=root
Group=root
Environment="BACKREST_BIND=0.0.0.0"
Environment="BACKREST_PORT=9898"
ExecStart=/usr/local/bin/backrest
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

> **Peringatan Keamanan:**  
> Menjalankan Backrest sebagai root memberikan akses penuh ke sistem. Pastikan dasbor web hanya dapat diakses dari jaringan tepercaya atau aktifkan autentikasi pada langkah berikutnya.

Setelah menyimpan, muat ulang daemon systemd dan aktifkan layanan:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now backrest
sudo systemctl status backrest --no-pager
```

Periksa port 9898:

```bash
ss -tulpn | grep 9898
```

Jika firewall aktif, izinkan akses ke port tersebut:

```bash
sudo ufw allow 9898/tcp
sudo ufw reload
```

## 3. Inisialisasi Dasbor dan Repositori Penyimpanan RustFS S3

Akses dasbor Backrest melalui peramban:

```
http://<ip-server>:9898
```

*Konfigurasi Awal*

- Isi **Instance ID** dengan nama unik untuk server ini, misalnya `forgejo-server`.
- **Autentikasi**: Jika hanya diakses dari jaringan lokal tepercaya, nonaktifkan autentikasi. Jika dapat diakses dari internet, **aktifkan autentikasi** dan buat kata sandi kuat.

Simpan konfigurasi awal.

*Menghubungkan Repositori RustFS*

1. Buka menu **Repositories**.
2. Klik **Add Repository**.
3. Isi **Nama repositori**, misalnya: `forgejo-backup-2026`.
4. Pada **Repository URI**, masukkan titik akhir S3 RustFS:

   ```
   s3:http://<ip-server-rustfs>:9000/rustfs-backup-2026
   ```

5. Pada bagian **Env Vars**, tambahkan dua variabel kredensial RustFS tanpa spasi:

   ```
   AWS_ACCESS_KEY_ID=<RUSTFS_ACCESS_KEY>
   AWS_SECRET_ACCESS_KEY=<RUSTFS_SECRET_KEY>
   ```

   Ganti `<RUSTFS_ACCESS_KEY>` dan `<RUSTFS_SECRET_KEY>` dengan kredensial RustFS Anda.

6. Buat kata sandi enkripsi yang sangat kuat. **Simpan di pengelola kata sandi.** Jika hilang, data cadangan tidak dapat didekripsi.

7. Klik **Test Connection** untuk memastikan koneksi ke RustFS berhasil.

8. Klik **Submit** untuk menyimpan repositori.

## 4. Pembuatan Rencana Pencadangan

Masuk ke menu **Plans** dan buat jadwal pencadangan baru.

1. Klik **Add Plan**.
2. Beri nama rencana, misalnya: `rustfs-forgejo-2026`.
3. Pilih **Repository** target yang telah dibuat (`forgejo-backup-2026`).
4. Pada bagian **Paths**, tambahkan jalur absolut yang akan dicadangkan:

   ```
   /etc/forgejo
   /var/lib/forgejo
   /etc/systemd/system/forgejo.service
   /usr/local/bin/forgejo
   ```

5. Pada bagian **Excludes**, tambahkan pola untuk mengabaikan berkas sementara dan log:

   ```
   **/tmp/**
   **/*.log
   ```

6. Pada bagian **Schedule**, gunakan ekspresi cron berikut agar pencadangan berjalan setiap jam pada menit ke-0:

   ```
   0 * * * *
   ```

7. Pada bagian **Retention Policy**, tentukan siklus hidup snapshot. Contoh:
   - Keep last: `24` (snapshot per jam)
   - Keep daily: `30`
   - Keep monthly: `12`

8. Simpan rencana tersebut.

Untuk memastikan semuanya berfungsi, klik **Backup Now** pada rencana tersebut. Pantau prosesnya hingga selesai dan pastikan tidak ada error.

## 5. Simulasi & Prosedur Pemulihan Bencana (Disaster Recovery)

Uji keandalan sistem pencadangan dengan menyimulasikan kerusakan total pada server Forgejo.

*Simulasi Kerusakan*

Hentikan layanan Forgejo dan hapus seluruh berkas penting:

```bash
sudo systemctl stop forgejo
sudo rm -rf /etc/forgejo /var/lib/forgejo /var/log/forgejo
sudo rm /usr/local/bin/forgejo /etc/systemd/system/forgejo.service
```

> **Peringatan:** Lakukan simulasi ini hanya pada server uji atau ketika Anda benar-benar ingin menguji pemulihan.

*Prosedur Pemulihan melalui Backrest*

1. Buka menu **Repositories** dan klik **Index Snapshots** pada repositori `forgejo-backup-2026` untuk menarik metadata terbaru dari RustFS.
2. Setelah indeks selesai, klik snapshot terbaru (berdasarkan waktu).
3. Buka **Snapshot Browser**, arahkan kursor ke direktori teratas (root `/`), lalu klik ikon **Restore**.
4. Pilih **Restore to path**.
5. Biarkan kolom lokasi tujuan kosong, lalu konfirmasi. Backrest akan mengunduh dan menempatkan seluruh struktur berkas ke jalur aslinya di host Ubuntu, termasuk:
   - `/etc/forgejo`
   - `/var/lib/forgejo`
   - `/etc/systemd/system/forgejo.service`
   - `/usr/local/bin/forgejo`

Tunggu proses restore selesai.

*Perbaikan Pasca-Restore*

Setelah restore selesai, buat kembali direktori log dan perbaiki hak kepemilikan serta izin eksekusi:

```bash
# Buat ulang direktori log
sudo mkdir -p /var/log/forgejo

# Kembalikan kepemilikan ke pengguna git
sudo chown -R git:git /var/lib/forgejo /etc/forgejo /var/log/forgejo

# Perbaiki izin direktori
sudo chmod -R 750 /var/lib/forgejo /var/log/forgejo
sudo chmod 770 /etc/forgejo

# Pastikan biner forgejo dapat dieksekusi
sudo chmod +x /usr/local/bin/forgejo

# Muat ulang systemd dan jalankan kembali Forgejo
sudo systemctl daemon-reload
sudo systemctl start forgejo
sudo systemctl status forgejo --no-pager
```

Verifikasi bahwa Forgejo berjalan dengan membuka `http://<ip-server>:3000` di peramban. Repositori dan data Anda harus kembali seperti semula.
