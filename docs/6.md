# Backup & Disaster Recovery

Sebuah sistem pencadangan yang andal adalah fondasi utama dari operasi infrastruktur yang tangguh. Pada lingkungan ini, saya memilih Restic sebagai mesin pencadangan karena performanya yang efisien dan dukungan enkripsi yang kuat, serta Backrest sebagai lapisan antarmuka web yang memudahkan pengelolaan dan pemantauan cadangan secara visual.

## 1. Instalasi Restic dan Backrest

Pertama-tama, kita siapkan komponen inti. Restic dapat langsung dipasang dari repositori resmi Ubuntu, sementara Backrest perlu diunduh secara manual dari rilis resmi GitHub karena tidak tersedia di repositori bawaan.

```bash
sudo apt update
sudo apt install -y restic

# Unduh arsip biner Backrest untuk arsitektur Linux AMD64
curl -fLo /tmp/backrest_Linux_x86_64.tar.gz \
  https://github.com/garethgeorge/backrest/releases/latest/download/backrest_Linux_x86_64.tar.gz

# Ekstrak ke direktori sementara dan jalankan skrip instalasi
mkdir -p /tmp/backrest-install
tar -xzvf /tmp/backrest_Linux_x86_64.tar.gz -C /tmp/backrest-install
cd /tmp/backrest-install
sudo ./install.sh
```

Jika ditemukan kendala izin eksekusi pada `install.sh`, cukup beri hak akses terlebih dahulu sebelum menjalankannya.

```bash
chmod +x install.sh
sudo ./install.sh
```

## 2. Menyesuaikan Layanan Systemd untuk Backrest

Secara default, skrip instalasi akan membuat unit systemd bernama `backrest.service` yang dikonfigurasi untuk berjalan pada pengguna biasa dan hanya terikat pada antarmuka localhost. Namun, karena kita memerlukan akses baca terhadap direktori data Forgejo (`/var/lib/forgejo`) dan dasbor web perlu dijangkau dari perangkat lain di jaringan, kita harus mengubah beberapa variabel lingkungan pada unit tersebut.

Buka berkas unit layanan yang terletak di `/etc/systemd/system/backrest.service`:

```bash
sudo nano /etc/systemd/system/backrest.service
```

Sesuaikan isinya menjadi seperti berikut:

```ini
[Unit]
Description=Backrest
After=network.target

[Service]
Type=simple
User=root
Group=root
Environment="BACKREST_BIND=0.0.0.0"
Environment="BACKREST_PORT=9898"
ExecStart=/usr/local/bin/backrest
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

**Catatan penting mengenai keamanan:**  
Mengubah pengguna menjadi *root* memang diperlukan agar Backrest dapat mengakses seluruh berkas sistem yang dicadangkan. Namun, konsekuensinya adalah dasbor web akan memiliki kewenangan penuh. Pastikan Anda hanya mengaksesnya dari jaringan internal yang terpercaya, atau aktifkan fitur autentikasi bawaan pada langkah selanjutnya jika terpaksa diekspos ke luar.

Setelah menyimpan perubahan, reload systemd dan aktifkan layanan agar berjalan otomatis:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now backrest
sudo systemctl status backrest --no-pager
```

Untuk memastikan bahwa port sudah terbuka dan mendengarkan, kita bisa periksa dengan perintah `ss`:

```bash
ss -tulpn | grep 9898
```

Apabila Anda mengaktifkan firewall UFW, jangan lupa untuk mengizinkan akses masuk ke port 9898:

```bash
sudo ufw allow 9898/tcp
sudo ufw reload
```

## 3. Menghubungkan Dasbor dengan Repositori RustFS via S3

Setelah layanan berjalan, buka peramban dan akses alamat berikut:

```
http://<ip-server>:9898
```

Saat pertama kali membuka dasbor, Anda akan diminta untuk mengatur *Instance ID*. Isilah dengan nama unik untuk mengenali server ini, misalnya `forgejo-server`. Untuk keamanan, jika dasbor hanya diakses dari lokal, Anda boleh menonaktifkan autentikasi. Namun jika ada potensi akses dari internet, sangat disarankan untuk mengaktifkan autentikasi dan segera membuat kata sandi yang kuat.

Selanjutnya, kita sambungkan Backrest ke repositori penyimpanan objek di RustFS. Pada menu navigasi, buka bagian **Repositories**, lalu klik **Add Repository**. Berikan nama yang deskriptif, misalnya `forgejo-backup-2026`. Untuk URI repositori, karena RustFS menyediakan antarmuka S3, gunakan format berikut:

```
s3:http://<ip-server-rustfs>:9000/rustfs-backup-2026
```

Pada kolom **Env Vars**, kita perlu memasukkan kredensial akses RustFS dalam bentuk variabel lingkungan. Pastikan tidak ada spasi di antara nilai:

```
AWS_ACCESS_KEY_ID=<RUSTFS_ACCESS_KEY>
AWS_SECRET_ACCESS_KEY=<RUSTFS_SECRET_KEY>
```

Ganti bagian `<RUSTFS_ACCESS_KEY>` dan `<RUSTFS_SECRET_KEY>` dengan kredensial yang sudah Anda buat sebelumnya. Jangan lupa untuk menentukan kata sandi enkripsi yang sangat kuat—simpan baik-baik di pengelola kata sandi karena tanpa kata sandi ini, proses dekripsi data cadangan tidak mungkin dilakukan. Setelah semua terisi, klik **Test Connection** untuk memastikan koneksi ke RustFS berhasil, lalu simpan repositori tersebut.

## 4. Menyusun Rencana Pencadangan Otomatis

Dengan repositori yang sudah siap, saatnya membuat jadwal pencadangan rutin. Buka menu **Plans** dan pilih **Add Plan**. Saya sarankan memberi nama rencana yang jelas, seperti `rustfs-forgejo-2026`, lalu pilih repositori target yang baru saja kita buat.

Pada bagian **Paths**, tambahkan direktori dan berkas-berkas krusial yang menjadi tulang punggung Forgejo:

```
/etc/forgejo
/var/lib/forgejo
/etc/systemd/system/forgejo.service
/usr/local/bin/forgejo
```

Untuk mengoptimalkan ukuran cadangan, kita juga bisa mengabaikan berkas-berkas yang tidak diperlukan, seperti log dan cache sementara. Tambahkan pola pengecualian berikut pada bagian **Excludes**:

```
**/tmp/**
**/*.log
```

Selanjutnya, atur jadwal eksekusi. Karena data repositori kode bersifat dinamis, saya menentukan interval pencadangan setiap jam tepat pada menit ke-0 menggunakan ekspresi cron:

```
0 * * * *
```

Terakhir, tentukan kebijakan retensi untuk mengatur siklus hidup snapshot. Contoh di bawah ini memastikan kita memiliki riwayat yang cukup untuk pemulihan tanpa menghabiskan kapasitas penyimpanan:

- Keep last: `24` (menyimpan snapshot per jam selama 24 jam terakhir)
- Keep daily: `30` (menyimpan satu snapshot per hari selama 30 hari)
- Keep monthly: `12` (menyimpan satu snapshot per bulan selama 12 bulan)

Simpan rencana tersebut. Untuk memastikan tidak ada kesalahan konfigurasi, Anda bisa langsung mengeklik tombol **Backup Now** pada rencana yang baru dibuat dan memantau prosesnya hingga selesai tanpa munculnya pesan galat.

## 5. Simulasi dan Prosedur Pemulihan Bencana

Bagian terpenting dari dokumentasi ini adalah memastikan bahwa proses pemulihan berjalan mulus ketika benar-benar dibutuhkan. Saya sangat menganjurkan untuk melakukan uji coba pemulihan secara berkala di lingkungan pengujian. Berikut adalah simulasi skenario terburuk: server Forgejo mengalami kerusakan total.

*Mensimulasikan Kerusakan*

Hentikan layanan Forgejo dan hapus seluruh berkas pentingnya secara paksa:

```bash
sudo systemctl stop forgejo
sudo rm -rf /etc/forgejo /var/lib/forgejo /var/log/forgejo
sudo rm /usr/local/bin/forgejo /etc/systemd/system/forgejo.service
```

*Langkah Pemulihan Melalui Backrest*

Kembali ke dasbor Backrest, buka menu **Repositories** dan klik **Index Snapshots** pada repositori `forgejo-backup-2026`. Proses ini akan menarik metadata terbaru dari RustFS agar kita bisa melihat daftar snapshot yang tersedia. Setelah selesai, pilih snapshot terbaru berdasarkan waktu, lalu buka **Snapshot Browser**.

Pada penelusur (*browser*) tersebut, arahkan kursor ke direktori paling atas (akar `/`), dan klik ikon **Restore**. Pilih opsi **Restore to path**, namun biarkan kolom lokasi tujuan tetap kosong. Dengan cara ini, Backrest akan mengembalikan seluruh struktur berkas ke jalur aslinya di sistem, meliputi:

- `/etc/forgejo`
- `/var/lib/forgejo`
- `/etc/systemd/system/forgejo.service`
- `/usr/local/bin/forgejo`

Tunggu hingga proses restore selesai—durasi tergantung pada ukuran data dan kecepatan jaringan.

*Perbaikan dan Verifikasi Pasca-Pemulihan*

Meskipun berkas-berkas utama sudah kembali, sering kali direktori log dan hak kepemilikan perlu diperbaiki secara manual. Jalankan perintah berikut untuk memastikan Forgejo dapat berjalan normal:

```bash
# Buat ulang direktori log yang mungkin hilang
sudo mkdir -p /var/log/forgejo

# Kembalikan kepemilikan ke pengguna git (sesuai dengan konfigurasi Forgejo)
sudo chown -R git:git /var/lib/forgejo /etc/forgejo /var/log/forgejo

# Atur ulang izin akses direktori
sudo chmod -R 750 /var/lib/forgejo /var/log/forgejo
sudo chmod 770 /etc/forgejo

# Pastikan biner utama memiliki izin eksekusi
sudo chmod +x /usr/local/bin/forgejo
```

Terakhir, muat ulang konfigurasi systemd dan nyalakan kembali layanan Forgejo:

```bash
sudo systemctl daemon-reload
sudo systemctl start forgejo
sudo systemctl status forgejo --no-pager
```
