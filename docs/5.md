Setelah server Git Forgejo berhasil berjalan di atas Ubuntu dengan Podman dan basis data SQLite3 berbasis berkas, muncul tantangan baru: mencadangkan data secara langsung saat kontainer aktif berisiko menyebabkan korupsi data karena berkas basis data terus berubah. Untuk mengatasinya, gunakan **Restic** sebagai mesin pencadangan modern yang menawarkan enkripsi sisi klien dan deduplikasi, serta **Backrest** sebagai antarmuka web yang dipasang langsung di host untuk memudahkan pengelolaan cadangan secara visual. Lingkungan yang digunakan masih sama, yaitu Ubuntu 26.04 LTS dengan Podman Engine 5.7.0, dan seluruh proses akan tetap menjaga kesederhanaan tanpa mengorbankan keandalan data.

Langkah pertama adalah memasang Restic dari repositori resmi Ubuntu. Jalankan perintah pembaruan paket dan instalasi biner Restic melalui terminal:

```bash
sudo apt update
sudo apt install -y restic
```

Selanjutnya, pasang Backrest dari rilis resmi GitHub. Unduh arsip untuk arsitektur Linux AMD64, ekstrak ke direktori sementara, lalu jalankan skrip instalasi resmi yang disediakan oleh pengembang:

```bash
curl -sSL https://github.com/garethgeorge/backrest/releases/latest/download/backrest_Linux_x86_64.tar.gz | tar -xz -C /tmp
cd /tmp/backrest
sudo ./install.sh
```

Skrip instalasi resmi tersebut akan menempatkan biner Backrest ke `/usr/local/bin/backrest` dan secara otomatis membuat unit systemd bernama `backrest.service` dengan variabel lingkungan `BACKREST_PORT=0.0.0.0:9898`. Variabel ini memastikan dasbor web dapat diakses dari seluruh antarmuka jaringan host, sehingga Anda tidak hanya bisa mengaksesnya dari lokal saja. Aktifkan dan jalankan layanan Backrest agar berjalan secara permanen dengan perintah berikut:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now backrest
sudo systemctl status backrest
```

Setelah layanan aktif, buka dasbor Backrest melalui peramban dengan mengarahkan ke `http://<alamat-ip-server>:9898`, misalnya `http://10.64.142.4:9898`. Pada halaman pengaturan awal, isi **Instance ID** dengan nama unik seperti `homelab-server` untuk membedakan mesin jika Anda memiliki banyak server, dan nonaktifkan autentikasi terlebih dahulu karena lingkungan ini bersifat lokal dan hanya diakses dalam jaringan tepercaya, lalu simpan konfigurasi.

Tambahkan repositori penyimpanan cadangan melalui menu **Repositories**. Pilih tipe yang sesuai dengan penyedia penyimpanan Anda, misalnya Backblaze B2 atau S3-compatible. Isi nama *bucket* dengan `forgejo-backup-2026`, dan buat kata sandi enkripsi yang kuat—kata sandi ini bersifat wajib karena Restic menerapkan enkripsi sisi klien, sehingga penyedia cloud tidak dapat membaca data Anda tanpa kunci tersebut. Seluruh konfigurasi Backrest, termasuk repositori dan rencana, akan tersimpan secara terpusat di `/etc/backrest/config.json`.

Buat rencana cadangan baru bernama `forgejo-daily-backup` pada menu **Plans**. Daftarkan dua lokasi sumber yang perlu dicadangkan secara persisten, yaitu volume data Forgejo yang menyimpan seluruh repositori dan basis data, serta direktori definisi Quadlet yang menjadi cetak biru konfigurasi kontainer:

```
/var/lib/containers/storage/volumes/forgejo-data/_data
/etc/containers/systemd
```

Agar proses pencadangan lebih efisien, terapkan pengecualian untuk berkas-berkas yang tidak perlu dicadangkan seperti `*.log` dan seluruh direktori sementara melalui pola `**/tmp/**`. Atur jadwal eksekusi menggunakan ekspresi cron menjadi `0 2 * * *` agar pencadangan berjalan otomatis setiap hari pukul 02:00 dini hari saat lalu lintas server sedang sepi. Pada kebijakan retensi, simpan 24 snapshot terakhir per jam, 30 snapshot harian, dan 12 snapshot bulanan—kombinasi ini memastikan Anda memiliki titik pemulihan yang cukup tanpa menghabiskan kapasitas penyimpanan secara berlebihan.

Untuk menjaga konsistensi absolut basis data SQLite3 Forgejo selama proses pencadangan berlangsung, tambahkan *hook* pre-backup berikut. Hook ini akan dieksekusi oleh Backrest tepat sebelum Restic mulai menyalin berkas:

```bash
podman exec -u 1000 forgejo forgejo dump --skip-repository
```

Perintah di atas memanfaatkan Podman untuk menjalankan utilitas bawaan Forgejo di dalam kontainer dengan identitas pengguna `1000`. Opsi `--skip-repository` sengaja ditambahkan agar proses *dump* hanya menghasilkan berkas arsip basis data dan konfigurasi tanpa menyalin repositori Git (yang sudah tersimpan utuh di dalam volume), sehingga ukuran *dump* tetap ringan dan proses berjalan cepat. Setelah pencadangan selesai, tambahkan *hook* post-backup berikut untuk membersihkan berkas *dump* sementara yang sudah tidak terpakai:

```bash
podman exec -u 1000 forgejo find /data -name "forgejo-dump-*.zip" -delete
```

Simpan rencana cadangan, lalu jalankan **Run Now** dari dasbor Backrest untuk memverifikasi bahwa pencadangan pertama berhasil tanpa kendala. Pantau log yang muncul untuk memastikan Restic berhasil terhubung ke penyimpanan cloud dan menyimpan snapshot awal.

Untuk skenario pemulihan bencana, hentikan layanan Forgejo terlebih dahulu agar tidak terjadi perubahan data selama proses restorasi berlangsung. Menghentikan kontainer sebelum memulihkan data adalah langkah krusial untuk mencegah konflik akses berkas dan korupsi:

```bash
sudo systemctl stop forgejo
```

Buka dasbor Backrest, pilih repositori `forgejo-backup-2026`, lalu telusuri daftar snapshot yang tersedia. Pilih snapshot target berdasarkan waktu yang diinginkan, dan lakukan **restore to original location** agar seluruh berkas dikembalikan ke jalur asalnya di dalam host. Setelah restorasi selesai, muat ulang konfigurasi systemd dan nyalakan kembali Forgejo untuk mengaktifkan layanan seperti sedia kala:

```bash
sudo systemctl daemon-reload
sudo systemctl start forgejo
```

Terakhir, pastikan status layanan aktif dengan `sudo systemctl status forgejo` dan verifikasi melalui antarmuka web Forgejo di `http://<alamat-ip-server>:3000`. Jika halaman utama dapat diakses dan repositori lama Anda masih utuh, maka proses pemulihan dinyatakan berhasil dan data telah kembali aman.
