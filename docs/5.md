Setelah server Git Forgejo berhasil berjalan di Ubuntu dengan Podman dan SQLite3, muncul tantangan baru: mencadangkan data secara langsung saat kontainer aktif berisiko menyebabkan korupsi data karena berkas basis data terus berubah. Untuk mengatasinya, gunakan Restic sebagai mesin pencadangan modern yang menawarkan enkripsi sisi klien dan deduplikasi, serta Backrest sebagai antarmuka web yang dipasang langsung di host untuk memudahkan pengelolaan cadangan secara visual. Lingkungan yang digunakan masih sama, yaitu Ubuntu 26.04 LTS dengan Podman Engine 5.7.0, dan seluruh proses akan tetap menjaga kesederhanaan tanpa mengorbankan keandalan data.

Langkah pertama adalah memasang Restic dari repositori resmi Ubuntu. Jalankan perintah pembaruan paket dan instalasi biner Restic melalui terminal:

sudo apt update
sudo apt install -y restic

Selanjutnya, pasang Backrest dari rilis resmi GitHub. Unduh arsip untuk arsitektur Linux AMD64, ekstrak ke direktori sementara, lalu jalankan skrip instalasi resmi yang disediakan oleh pengembang:

curl -sLO [https://github.com/garethgeorge/backrest/releases/latest/download/backrest_Linux_x86_64.tar.gz](https://github.com/garethgeorge/backrest/releases/latest/download/backrest_Linux_x86_64.tar.gz)
mkdir backrest && tar -xzvf backrest_Linux_x86_64.tar.gz -C backrest
cd backrest && ./install.sh

Skrip instalasi resmi tersebut akan menempatkan biner Backrest ke /usr/local/bin/backrest dan secara otomatis membuat unit systemd bernama backrest.service. Secara default, skrip ini tidak mengizinkan akses dari luar. Oleh karena itu, Anda harus mengedit berkas /etc/systemd/system/backrest.service dan menambahkan variabel lingkungan resmi BACKREST_BIND=0.0.0.0 dan BACKREST_PORT=9898 di dalam blok [Service]. Variabel ini memastikan dasbor web dapat diakses dari seluruh antarmuka jaringan host, sehingga Anda tidak hanya bisa mengaksesnya dari localhost saja. Aktifkan dan jalankan layanan Backrest agar berjalan secara permanen dengan perintah berikut:

sudo systemctl daemon-reload
sudo systemctl enable --now backrest
sudo systemctl status backrest

Setelah layanan aktif, buka dasbor Backrest melalui peramban dengan mengarahkan ke http://:9898, misalnya [http://10.64.142.208:9898](http://10.64.142.208:9898). Pada halaman pengaturan awal, isi Instance ID dengan nama unik seperti homelab-server untuk membedakan mesin jika Anda memiliki banyak server. Nonaktifkan autentikasi terlebih dahulu karena lingkungan ini bersifat lokal dan hanya diakses dalam jaringan tepercaya, lalu simpan konfigurasi.

Tambahkan repositori penyimpanan cadangan melalui menu Repositories. Pilih tipe yang sesuai dengan penyedia penyimpanan Anda, misalnya Backblaze B2 atau S3-compatible. Isi nama bucket dengan forgejo-backup-2026, dan buat kata sandi enkripsi yang kuat—kata sandi ini bersifat wajib karena Restic menerapkan enkripsi sisi klien, sehingga penyedia cloud tidak dapat membaca data Anda tanpa kunci tersebut. Berbeda dengan instalasi Docker, pada instalasi biner/systemd resmi ini, seluruh konfigurasi Backrest, termasuk enkripsi dan rencana cadangan, akan tersimpan secara terpusat di direktori home pengguna yang menjalankannya di jalur ~/.config/backrest/config.json.

Buat rencana cadangan baru bernama forgejo-daily-backup pada menu Plans. Daftarkan dua lokasi sumber yang perlu dicadangkan secara persisten, yaitu volume data Forgejo yang menyimpan seluruh repositori dan basis data, serta direktori definisi Quadlet yang menjadi cetak biru konfigurasi kontainer:

/var/lib/containers/storage/volumes/forgejo-data/_data
/etc/containers/systemd

Agar proses pencadangan lebih efisien, terapkan pengecualian untuk berkas-berkas yang tidak perlu dicadangkan seperti *.log dan seluruh direktori sementara melalui pola **/tmp/**. Atur jadwal eksekusi menggunakan ekspresi cron menjadi 0 2 * * * agar pencadangan berjalan otomatis setiap hari pukul 02:00 dini hari saat lalu lintas server sedang sepi. Pada kebijakan retensi (Prune Policy), aktifkan fitur prune otomatis setelah pencadangan selesai, lalu simpan 24 snapshot terakhir per jam, 30 snapshot harian, dan 12 snapshot bulanan—kombinasi ini memastikan Anda memiliki titik pemulihan yang cukup tanpa menghabiskan kapasitas penyimpanan secara berlebihan.

Untuk menjaga konsistensi absolut basis data SQLite3 Forgejo selama proses pencadangan berlangsung, tambahkan hook pre-backup berikut. Hook ini akan dieksekusi oleh Backrest tepat sebelum Restic mulai menyalin berkas:

podman exec -u 1000 forgejo forgejo dump --skip-repository --work-path /data

Perintah di atas memanfaatkan Podman untuk menjalankan utilitas bawaan Forgejo di dalam kontainer dengan identitas pengguna 1000. Opsi --skip-repository sengaja ditambahkan agar proses dump hanya menghasilkan berkas arsip basis data dan konfigurasi tanpa menyalin repositori Git (yang sudah tersimpan utuh di dalam volume), serta opsi --work-path /data digunakan untuk memastikan agar berkas zip hasil dump langsung masuk ke dalam volume terikat. Setelah pencadangan selesai, tambahkan hook post-backup berikut untuk membersihkan berkas dump sementara yang sudah tidak terpakai agar tidak memakan ruang penyimpanan lokal:

podman exec -u 1000 forgejo find /data -name "forgejo-dump-*.zip" -delete

Simpan rencana cadangan, lalu jalankan Run Now dari dasbor Backrest untuk memverifikasi bahwa pencadangan pertama berhasil tanpa kendala. Pantau log yang muncul di lokasi default ~/.local/share/backrest/processlogs/backrest.log untuk memastikan Restic berhasil terhubung ke penyimpanan cloud dan menyimpan snapshot awal.

Untuk skenario pemulihan bencana (Disaster Recovery), hentikan layanan Forgejo terlebih dahulu agar tidak terjadi perubahan data selama proses restorasi berlangsung. Menghentikan kontainer yang dikelola Systemd/Quadlet sebelum memulihkan data adalah langkah krusial untuk mencegah konflik akses berkas dan korupsi data:

sudo systemctl stop forgejo

Buka dasbor Backrest, pilih repositori forgejo-backup-2026, lalu telusuri daftar snapshot yang tersedia. Pilih snapshot target berdasarkan waktu yang diinginkan, dan lakukan *restore to original location* agar seluruh berkas dikembalikan ke jalur asalnya di dalam host. Setelah restorasi selesai, pastikan kepemilikan berkas (UID/GID) pada volume host tetap mengarah ke pengguna kontainer (1000), lalu muat ulang konfigurasi systemd dan nyalakan kembali Forgejo untuk mengaktifkan layanan seperti sedia kala:

sudo systemctl daemon-reload
sudo systemctl start forgejo

Terakhir, pastikan status layanan aktif dengan sudo systemctl status forgejo dan verifikasi melalui antarmuka web Forgejo di http://:3000. Jika halaman utama dapat diakses dan repositori lama Anda masih utuh, maka proses pemulihan dinyatakan berhasil dan data telah kembali aman.
