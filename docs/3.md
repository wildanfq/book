Dalam dunia pengembangan perangkat lunak modern, kontainer telah menjadi standar untuk mengemas aplikasi beserta seluruh dependensinya, sehingga dapat berjalan secara identik di berbagai lingkungan. Sebuah kontainer adalah unit isolasi yang memanfaatkan dua fitur utama kernel Linux: *namespaces* untuk membatasi pandangan proses terhadap sistem berkas, jaringan, dan pengenal proses, serta *cgroups* untuk mengatur alokasi sumber daya seperti CPU, memori, dan I/O. Berbeda dengan mesin virtual yang meniru seluruh perangkat keras dan menyertakan kernel sendiri, kontainer berbagi kernel dengan sistem operasi induk. Hal ini membuat *image* kontainer jauh lebih kecil—umumnya hanya puluhan megabita—dan mampu menyala dalam hitungan detik.

Tiga komponen utama dalam ekosistem ini adalah *image*, kontainer, dan *registry*. *Image* merupakan cetak biru statis yang tersusun dari lapisan-lapisan *read-only*; setiap lapisan dibentuk oleh satu instruksi dalam *Containerfile*, seperti menyalin berkas atau memasang paket. Saat sebuah kontainer dijalankan dari *image*, sebuah lapisan tulis (*read-write*) ditambahkan di atas tumpukan lapisan tersebut. Semua perubahan yang terjadi selama kontainer berjalan hanya tersimpan di lapisan ini dan akan hilang ketika kontainer dihapus. *Registry* berfungsi sebagai gudang untuk menyimpan dan mendistribusikan *image*, dengan contoh populer seperti Docker Hub dan Quay.

Podman (*Pod Manager*) adalah mesin kontainer yang sepenuhnya mematuhi standar OCI (*Open Container Initiative*). Podman menyediakan antarmuka baris perintah yang kompatibel dengan Docker, sehingga pengguna dapat dengan mudah beralih, bahkan cukup dengan membuat alias `alias docker=podman`. Podman memiliki dua keunggulan utama: arsitektur *daemonless* yang tidak memerlukan proses latar belakang istimewa seperti `dockerd`, serta dukungan mode *rootless* yang memungkinkan pengguna biasa menjalankan kontainer dengan aman tanpa hak akses *root*. Keunggulan inilah yang menjadikan Podman pilihan yang tepat untuk memulai perjalanan Anda dengan kontainer.

Untuk memulai, pada distribusi Debian atau Ubuntu, instal Podman dengan perintah `sudo apt update && sudo apt install podman -y`. Setelah selesai, verifikasi instalasi menggunakan `podman version`. Alur kerja paling dasar dimulai dengan mencari dan menjalankan *image* yang tersedia. Gunakan `podman search docker.io/busybox` untuk menemukan *image* BusyBox, lalu tarik dengan `podman pull docker.io/library/busybox`. Setelah terunduh, Anda dapat menjalankan kontainer interaktif melalui `podman run -it docker.io/library/busybox`. Untuk melihat kontainer yang sedang berjalan, gunakan `podman ps`. Kontainer dapat dihentikan dengan `podman stop <id_container>` dan dihapus dengan `podman rm <id_container>`. Jika *image* sudah tidak diperlukan, bersihkan dengan `podman rmi <id_image>`.

Ketika *image* publik belum memenuhi kebutuhan, Podman memungkinkan Anda membangun *image* kustom menggunakan *Containerfile*. Strategi *multi-stage build* sangat dianjurkan agar *image* akhir hanya berisi biner aplikasi tanpa komponen tambahan yang tidak diperlukan, sehingga ukurannya tetap minimal. Sebagai contoh, kita akan membangun aplikasi REST API kecil dengan bahasa Go yang menangani *endpoint* `/tasks`. Pertama, siapkan direktori proyek dan inisialisasi modul Go:
```bash
mkdir tasks-api && cd tasks-api
go mod init tasks-api
```

Selanjutnya, tulis kode aplikasi di `main.go`:

```go
package main

import (
	"encoding/json"
	"log"
	"net/http"
)

type Task struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
}

var (
	tasks  []Task
	nextID = 1
)

func getTasks(w http.ResponseWriter, _ *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(tasks)
}

func createTask(w http.ResponseWriter, r *http.Request) {
	var task Task
	if err := json.NewDecoder(r.Body).Decode(&task); err != nil {
		http.Error(w, "Invalid JSON", http.StatusBadRequest)
		return
	}
	task.ID = nextID
	nextID++
	tasks = append(tasks, task)
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	json.NewEncoder(w).Encode(task)
}

func taskHandler(w http.ResponseWriter, r *http.Request) {
	switch r.Method {
	case http.MethodGet:
		getTasks(w, r)
	case http.MethodPost:
		createTask(w, r)
	default:
		http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
	}
}

func main() {
	http.HandleFunc("/tasks", taskHandler)
	log.Println("Server running on http://localhost:8080")
	log.Fatal(http.ListenAndServe(":8080", nil))
}
```

Kode ini mendefinisikan struktur `Task`, dua *handler* untuk mengambil dan menambah tugas, serta *router* sederhana yang membedakan metode GET dan POST.

Setelah kode siap, buat *Containerfile* di direktori yang sama:

```dockerfile
FROM golang:1.26-alpine AS builder
WORKDIR /app
COPY go.mod ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o tasks .

FROM scratch
WORKDIR /app
COPY --from=builder /app/tasks .
EXPOSE 8080
CMD ["./tasks"]
```

Tahap pertama (`builder`) menggunakan *image* `golang:1.26-alpine` untuk mengunduh dependensi dan mengkompilasi kode menjadi biner statis bernama `tasks`. Dengan menyalin `go.mod` terlebih dahulu sebelum seluruh kode, Podman dapat menyimpan *cache* lapisan unduhan modul, sehingga proses *build* berikutnya menjadi lebih cepat jika tidak ada perubahan pada `go.mod`. Tahap kedua dimulai dari *image* kosong `scratch` yang tidak memiliki *shell* atau utilitas apa pun; biner hasil kompilasi disalin ke direktori `/app`, port `8080` dideklarasikan, dan perintah `CMD` akan menjalankan aplikasi saat kontainer dimulai. Bangun *image* dengan `podman build -t tasks .`. Setelah selesai, jalankan kontainer di latar belakang:
```bash
podman run -d -p 8080:8080 localhost/tasks
```
Uji API dengan `curl http://localhost:8080/tasks`.

Setelah *image* kustom tercipta, Anda dapat membagikannya ke *registry*. Login ke Docker Hub dengan `podman login docker.io`, beri *tag* baru yang mengarah ke repositori Anda (`podman tag localhost/tasks docker.io/username/tasks`), lalu unggah dengan `podman push docker.io/username/tasks`.

Dalam praktik nyata, sebuah aplikasi sering terdiri dari beberapa kontainer yang harus berjalan bersama. Podman menyediakan dukungan *orchestration* melalui perintah `podman compose`, yang merupakan *wrapper* ringan di sekitar penyedia *compose* seperti `podman-compose` atau `docker-compose`. Pastikan salah satunya terpasang; jika belum, instal dengan `sudo apt install podman-compose`. Mari kita gabungkan backend Go dengan Caddy sebagai *reverse proxy*. Buat berkas `Caddyfile` dengan isi:
```
:80 {
    reverse_proxy backend:8080
}
```
Kemudian buat `docker-compose.yml`:

```yaml
services:
  backend:
    build: .
    expose:
      - "8080"

  caddy:
    image: caddy:alpine
    ports:
      - "8081:80"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
    depends_on:
      - backend
```

Berkas ini mendefinisikan dua layanan. Layanan `backend` dibangun dari *Containerfile* di direktori proyek dan hanya membuka port `8080` di dalam jaringan virtual yang dibuat secara otomatis oleh Compose. Layanan `caddy` menggunakan *image* `caddy:alpine`, memetakan port `8081` di *host* ke port `80` di dalam kontainer. Pemetaan ke port di atas 1024 diperlukan karena dalam mode *rootless*, Podman tidak mengizinkan pengikatan ke port sistem yang lebih rendah (di bawah 1024). Konfigurasi Caddy dipasang sebagai volume *read-only* (`:ro`), dan `depends_on` memastikan backend dinyalakan terlebih dahulu. Jalankan seluruh tumpukan dengan `podman compose up -d`. Caddy kini mendengarkan di `localhost:8081` dan meneruskan permintaan ke backend. Untuk menghentikan dan membersihkan semua layanan, gunakan `podman compose down`.

Selama pengoperasian, masalah dapat muncul. Jika kontainer gagal berjalan, langkah pertama adalah memeriksa *log* dengan `podman logs <nama_container>`. Untuk informasi lebih detail, gunakan `podman inspect <nama_container>` dan perhatikan *exit code* serta variabel lingkungan. Untuk penyelidikan langsung, Anda dapat masuk ke dalam kontainer yang bermasalah dengan mengganti *entrypoint*: `podman run -it --entrypoint /bin/sh <nama_image>`. Agar lingkungan tetap bersih, lakukan pembersihan berkala dengan `podman system prune -a`; perintah ini akan menghapus semua *image*, kontainer, dan jaringan yang tidak terpakai.
