# Orkestrasi Kontainer dengan Podman

## 1. Arsitektur dan Instalasi Podman
Podman (Pod Manager) adalah mesin kontainer berbasis standar OCI (*Open Container Initiative*) yang dirancang sebagai pengganti langsung (*drop-in replacement*) untuk Docker. Keunggulan utamanya terletak pada arsitektur *daemonless* (tanpa proses latar belakang istimewa) dan dukungan mode *rootless*, memungkinkan pengguna biasa mengeksekusi kontainer dengan aman tanpa hak akses administrator. Anda dapat memasang Podman di distribusi berbasis Debian/Ubuntu menggunakan pengelola paket resmi.

```bash
sudo apt update
sudo apt install -y podman
podman version
```

Alur kerja dasar dimulai dengan mencari citra di registri publik, menariknya ke lokal, menjalankannya secara interaktif, lalu membersihkannya. Anda dapat mencari citra BusyBox, mengunduhnya, menjalankannya, lalu memeriksa statusnya sebelum menghapus citra tersebut.

```bash
podman search docker.io/busybox
podman pull docker.io/library/busybox
podman run -it docker.io/library/busybox
podman ps
podman stop <id_container> && podman rm <id_container>
podman rmi <id_image>
```

## 2. Pembuatan Citra Kustom
Podman memungkinkan pembuatan citra secara spesifik menggunakan *Containerfile*. Pendekatan *multi-stage build* sangat direkomendasikan untuk menekan ukuran akhir citra karena hanya akan memuat biner kompilasi tanpa menyertakan perangkat pengembangan. Sebagai studi kasus, buat direktori proyek REST API berbasis bahasa Go dan inisialisasikan modulnya.

```bash
mkdir tasks-api && cd tasks-api
go mod init tasks-api
```

Buat berkas logika aplikasi `main.go` yang akan menyediakan *endpoint* `/tasks` untuk menangani metode GET dan POST secara sederhana.

```go
package main

import (
	"encoding/json"
	"log"
	"net/http"
)

type Task struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
}

var (
	tasks  []Task
	nextID = 1
)

func getTasks(w http.ResponseWriter, _ *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(tasks)
}

func createTask(w http.ResponseWriter, r *http.Request) {
	var task Task
	if err := json.NewDecoder(r.Body).Decode(&task); err != nil {
		http.Error(w, "Invalid JSON", http.StatusBadRequest)
		return
	}
	task.ID = nextID
	nextID++
	tasks = append(tasks, task)
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	json.NewEncoder(w).Encode(task)
}

func taskHandler(w http.ResponseWriter, r *http.Request) {
	switch r.Method {
	case http.MethodGet:
		getTasks(w, r)
	case http.MethodPost:
		createTask(w, r)
	default:
		http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
	}
}

func main() {
	http.HandleFunc("/tasks", taskHandler)
	log.Println("Server running on http://localhost:8080")
	log.Fatal(http.ListenAndServe(":8080", nil))
}
```

Buat *Containerfile* di direktori yang sama. Tahap pertama (`builder`) akan mengunduh dependensi dan mengompilasi kode menjadi biner statis. Tahap kedua akan memindahkan biner tersebut ke citra basis `scratch` (citra kosong tanpa *shell*) untuk menjamin keamanan dan ukuran yang ultra-ringan.

```dockerfile
FROM golang:1.26-alpine AS builder
WORKDIR /app
COPY go.mod ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o tasks .

FROM scratch
WORKDIR /app
COPY --from=builder /app/tasks .
EXPOSE 8080
CMD ["./tasks"]
```

Bangun citra dari *Containerfile* tersebut, lalu jalankan di latar belakang dan uji ketersediaan API-nya melalui terminal. Setelah berhasil, Anda dapat mengautentikasi dan mengunggah citra tersebut ke Docker Hub.

```bash
podman build -t tasks .
podman run -d -p 8080:8080 localhost/tasks
curl http://localhost:8080/tasks

podman login docker.io
podman tag localhost/tasks docker.io/username/tasks
podman push docker.io/username/tasks
```

## 3. Orkestrasi Multi-Kontainer dengan Compose
Untuk arsitektur aplikasi kompleks yang membutuhkan kolaborasi antarkontainer, gunakan `podman compose` yang mematuhi standar spesifikasi Compose. Pastikan paket pendukung seperti `podman-compose` telah terpasang. Sebagai contoh, kita akan menggabungkan API Go dengan Caddy sebagai *reverse proxy*. Buat berkas konfigurasi `Caddyfile`.

```text
:80 {
    reverse_proxy backend:8080
}
```

Selanjutnya, buat definisi orkestrasi `docker-compose.yml`. Layanan `backend` akan dibangun dari direktori lokal tanpa pemetaan porta ke luar, sementara layanan `caddy` akan memetakan porta 8081 dari host ke dalam kontainer. Karena beroperasi dalam mode *rootless*, Podman membatasi pengikatan (bind) ke porta di bawah 1024.

```yaml
services:
  backend:
    build: .
    expose:
      - "8080"

  caddy:
    image: caddy:alpine
    ports:
      - "8081:80"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
    depends_on:
      - backend
```

Eksekusi tumpukan layanan tersebut secara bersamaan. Lalu lintas kini akan mengalir dari `localhost:8081` menuju Caddy dan diteruskan ke backend secara internal. Jika terjadi anomali, periksa log aplikasi atau inspeksi variabel lingkungannya. Bersihkan seluruh lingkungan kontainer yang tidak terpakai secara rutin untuk menghemat penyimpanan lokal.

```bash
podman compose up -d
podman compose down
podman logs <nama_container>
podman inspect <nama_container>
podman system prune -a
```
