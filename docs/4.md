Prasyarat Server Linux dengan systemd (contoh: Debian 11+, Ubuntu 20.04/22.04). Podman versi 4.4+ sudah terpasang (bila perlu `sudo apt install podman`). Akses sudo tersedia. Port 3000 (antarmuka web) dan 222 (SSH Git) tidak dipakai atau diblokir *firewall*. Di komputer lokal sudah ada Git dan OpenSSH. Siapkan nama domain yang diarahkan ke IP publik server jika ingin mengaktifkan HTTPS. Jika semua sudah tersedia, kita mulai dari fondasi kontainer.

Buat direktori penyimpanan definisi Quadlet: `sudo mkdir -p /etc/containers/systemd`. Semua berkas yang akan dibuat disimpan di sini agar Podman dan systemd mengenalinya. Pertama, buat jaringan terpisah agar kontainer terisolasi. Jalankan `sudo nano /etc/containers/systemd/forgejo.network` dan isi dengan dua baris berikut:

```
[Network]
NetworkName=forgejo
```

Simpan berkas; ini akan menghasilkan jaringan *bridge* bernama `forgejo`. Selanjutnya, buat volume persisten untuk data Forgejo: `sudo nano /etc/containers/systemd/forgejo-data.volume` dan tulis:

```
[Volume]
VolumeName=forgejo-data
```

Simpan kembali. Podman akan mengelola letak fisik volume secara otomatis di `/var/lib/containers/storage/volumes/`.

Sekarang definisikan kontainer Forgejo dengan `sudo nano /etc/containers/systemd/forgejo.container`. Salin konfigurasi berikut yang sudah disesuaikan agar berjalan optimal:

```
[Container]
ContainerName=forgejo
Environment=USER_UID=1000
Environment=USER_GID=1000
Image=codeberg.org/forgejo/forgejo:10
Network=forgejo.network
PublishPort=3000:3000
PublishPort=222:22
Volume=forgejo-data:/data

[Service]
Restart=always

[Install]
WantedBy=default.target
```

Beberapa catatan: `USER_UID` dan `USER_GID` harus disetel ke UID/GID pengguna non-root pertama di sistem (biasanya 1000; cek dengan `id` jika berbeda). Tag `:10` menggunakan versi stabil; Anda bisa menggantinya ke versi lebih baru saat pembaruan. `PublishPort=3000:3000` meneruskan antarmuka web, `PublishPort=222:22` meneruskan port SSH Git yang sengaja dipilih 222 agar tidak bertabrakan dengan SSH server. Volume `forgejo-data:/data` memasang seluruh data di dalam kontainer ke volume persisten.

Simpan berkas, lalu muat ulang systemd dan nyalakan layanan: `sudo systemctl daemon-reload && sudo systemctl start forgejo && sudo systemctl enable forgejo`. Saat pertama dijalankan, Podman mengunduh citra, membuat jaringan, volume, dan kontainer. Periksa status dengan `sudo systemctl status forgejo`; pastikan `active (running)`. Buka peramban dan akses `http://<alamat-ip-server>:3000`. Anda akan melihat halaman instalasi Forgejo. Isi pengaturan: **Database Type** pilih `SQLite3`; **Server Domain** isi sementara dengan IP server (misalnya `192.168.1.100`); **SSH Port** ubah menjadi `222`; di bagian **Administrator Account**, tentukan nama pengguna, kata sandi, dan surel admin. Klik **Install Forgejo**. Tunggu beberapa detik, lalu login dengan akun admin yang baru dibuat.

Agar dapat mendorong kode via SSH, tambahkan kunci publik lokal ke Forgejo. Di komputer lokal, jika belum memiliki pasangan kunci, jalankan `ssh-keygen -t ed25519 -C "komentar"` dan salin isi `~/.ssh/id_ed25519.pub`. Di antarmuka web, buka **Settings > SSH / GPG Keys**, tempel kunci publik tersebut, lalu simpan. Uji koneksi dengan `ssh -F /dev/null git@<alamat-ip-server> -p 222`. Bila muncul sapaan otentikasi sukses, koneksi siap. Buat repositori baru di web, misalnya `proyek-perdana`. Di terminal lokal, buat proyek kecil dan inisialisasi Git: `mkdir proyek-perdana && cd proyek-perdana && git init && git branch -M main`, buat berkas `README.md`, komit, lalu tambahkan remote: `git remote add origin ssh://git@<alamat-ip-server>:222/<username>/proyek-perdana.git`. Dorong dengan `git push -u origin main`. Repositori akan muncul di web; server Git dasar telah berfungsi.

Untuk mengamankan akses dengan domain dan HTTPS, pasang Caddy. Pertama, pastikan domain seperti `git.example.com` sudah diarahkan ke IP server melalui DNS (A record). Di server, tambahkan repositori resmi Caddy dan instal: `sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https`, lalu ikuti instruksi di dokumentasi Caddy untuk menambahkan GPG key dan daftar sumber, akhiri dengan `sudo apt update && sudo apt install caddy -y`. Setelah terpasang, edit konfigurasi Caddy dengan `sudo nano /etc/caddy/Caddyfile`. Hapus isi awal, tulis:

```
git.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

Simpan dan tutup. Caddy akan otomatis meminta sertifikat Let's Encrypt dan melayani HTTPS.

Sesuaikan pengaturan Forgejo agar bekerja di balik *proxy*. Edit berkas `app.ini` di dalam volume: `sudo nano /var/lib/containers/storage/volumes/forgejo-data/_data/gitea/conf/app.ini`. Cari bagian `[server]` dan pastikan berisi:

```ini
[server]
DOMAIN       = git.example.com
ROOT_URL     = https://git.example.com/
HTTP_PORT    = 3000
SSH_DOMAIN   = git.example.com
SSH_PORT     = 222
```

Penambahan `SSH_DOMAIN` dan `SSH_PORT` memastikan URL kloning SSH yang ditampilkan di antarmuka menggunakan domain dan port kustom dengan benar. Kemudian tambahkan blok keamanan agar hanya *proxy* dari localhost yang dipercaya:

```ini
[security]
REVERSE_PROXY_TRUSTED_PROXIES = 127.0.0.0/8,::1/128
```

Simpan berkas, lalu perketat akses port 3000 dengan firewall. Misalnya dengan UFW: `sudo ufw deny 3000` dan `sudo ufw allow from 127.0.0.1 to any port 3000 proto tcp`. Port 222 tetap terbuka untuk SSH Git. Restart layanan: `sudo systemctl restart forgejo && sudo systemctl restart caddy`. Akses `https://git.example.com`; seharusnya muncul halaman login dengan kunci gembok hijau. Server pribadi kini aman dan siap dipakai.

**Pembaruan dan pengembalian versi.** Sebelum memperbarui, buat cadangan volume dengan `sudo tar -czf forgejo-backup-$(date +%Y%m%d).tar.gz -C /var/lib/containers/storage/volumes/forgejo-data/_data .`. Untuk naik versi, edit `forgejo.container`, ubah tag citra (misal dari `:10` ke `:11`), simpan, lalu jalankan `sudo systemctl daemon-reload`, `sudo podman pull codeberg.org/forgejo/forgejo:11`, dan `sudo systemctl restart forgejo`. Forgejo akan menjalankan migrasi otomatis; cek antarmuka untuk memastikan versi baru. Jika terjadi masalah, hentikan layanan (`sudo systemctl stop forgejo`), hapus isi volume, pulihkan dari cadangan `sudo tar -xzf forgejo-backup-20260101.tar.gz -C /var/lib/containers/storage/volumes/forgejo-data/_data`, sesuaikan kepemilikan dengan `sudo chown -R 1000:1000 /var/lib/containers/storage/volumes/forgejo-data/_data`, kembalikan tag citra ke semula di `forgejo.container`, dan nyalakan kembali `sudo systemctl daemon-reload && sudo systemctl start forgejo`.

**Pencadangan otomatis dengan Restic dan Backrest.** Pasang Restic: `sudo apt install restic` atau unduh biner dari repositori resmi. Siapkan bucket di Backblaze B2 atau Cloudflare R2, lalu set variabel lingkungan untuk repositori: `export RESTIC_REPOSITORY="s3:..."`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, dan `RESTIC_PASSWORD`. Inisialisasi repositori dengan `restic init`. Lakukan pencadangan manual pertama sebagai uji coba: `restic backup /var/lib/containers/storage/volumes/forgejo-data/_data`. Agar pencadangan berjalan rutin dan terpantau, gunakan Backrest sebagai kontainer. Buat unit Quadlet baru: `sudo nano /etc/containers/systemd/backrest.container`, isi dengan konfigurasi yang memetakan port UI (misal `9898`), volume `forgejo-data` secara *read-only*, serta variabel lingkungan kredensial Restic. Contoh:

```
[Container]
ContainerName=backrest
Image=garethgeorge/backrest:latest
PublishPort=9898:9898
Volume=backrest-config:/config
Volume=/var/lib/containers/storage/volumes/forgejo-data/_data:/data:ro
Environment=RESTIC_REPOSITORY=s3:...
Environment=AWS_ACCESS_KEY_ID=...
Environment=AWS_SECRET_ACCESS_KEY=...
Environment=RESTIC_PASSWORD=...
[Service]
Restart=always
[Install]
WantedBy=default.target
```

Muat ulang systemd dan jalankan: `sudo systemctl daemon-reload && sudo systemctl enable --now backrest`. UI Backrest dapat diakses di `http://<ip>:9898`. Untuk keamanan, tambahkan blok `backup.example.com { reverse_proxy 127.0.0.1:9898 }` di Caddyfile agar UI ikut terenkripsi. Di dalam Backrest, atur jadwal pencadangan otomatis dan pantau riwayat. Pemulihan data dapat dilakukan lewat antarmuka atau via `restic restore latest --target /lokasi-pemulihan`.
