Membangun server Git pribadi kini dapat dilakukan dengan mudah menggunakan Forgejo, sebuah platform hosting git sumber terbuka yang ringan dan menjadi alternatif menarik dari GitHub maupun GitLab Community Edition. Lingkungan yang digunakan dalam panduan ini adalah Ubuntu 26.04 LTS dengan alokasi 2 CPU dan memori 2 GiB, serta Podman Engine versi 5.7.0. Agar proses pembelajaran tetap sederhana dan mudah diikuti, konfigurasi sengaja tidak menyertakan enkripsi HTTPS dan mekanisme pencadangan.

Podman Quadlet menawarkan cara deklaratif untuk mendefinisikan kontainer, volume, dan jaringan melalui berkas-berkas yang disimpan di direktori `/etc/containers/systemd`. Systemd akan membaca berkas-berkas tersebut dan secara otomatis menghasilkan unit layanan yang sesuai, sehingga pengelolaan kontainer menjadi lebih terintegrasi dengan sistem. Sebagai langkah awal, buat direktori yang dibutuhkan dengan perintah `sudo mkdir -p /etc/containers/systemd`.

Server Git memerlukan jaringan internal yang terisolasi agar lalu lintas antar kontainer tetap terkendali, serta penyimpanan persisten agar data repositori tidak hilang saat kontainer dihidupkan ulang. Untuk itu, buat berkas bernama `forgejo.network` di dalam direktori tersebut dengan menggunakan `sudo nano /etc/containers/systemd/forgejo.network` dan isikan konfigurasi berikut:

```ini
[Network]
NetworkName=forgejo
```

Selanjutnya, definisikan volume persisten dengan nama `forgejo-data` melalui berkas `sudo nano /etc/containers/systemd/forgejo-data.volume`. Volume ini akan menampung semua data Forgejo di luar siklus hidup kontainer, sehingga repositori tetap aman meskipun kontainer diganti. Isi berkasnya cukup singkat:

```ini
[Volume]
VolumeName=forgejo-data
```

Konfigurasi kontainer Forgejo sendiri ditulis dalam berkas `sudo nano /etc/containers/systemd/forgejo.container`. Berkas ini akan membuka port `3000` untuk antarmuka web dan port `222` untuk akses Git melalui SSH. Port `222` sengaja dipilih agar tidak bertabrakan dengan layanan SSH bawaan mesin virtual yang umumnya menggunakan port `22`. Salin konfigurasi lengkap berikut ini ke dalam berkas tersebut:

```ini
[Container]
ContainerName=forgejo
Image=codeberg.org/forgejo/forgejo:14
Environment=USER_UID=1000
Environment=USER_GID=1000
Network=forgejo.network
PublishPort=3000:3000
PublishPort=222:22
Volume=forgejo-data:/data

[Service]
Restart=always

[Install]
WantedBy=multi-user.target
```

Pada konfigurasi di atas, `ContainerName` memberikan nama unik pada kontainer. `Image` menarik Forgejo versi 14 langsung dari Codeberg. Dua variabel lingkungan `USER_UID` dan `USER_GID` disetel ke `1000` agar identitas pengguna di dalam kontainer selaras dengan pengguna pertama di host, sehingga berkas-berkas di volume memiliki izin yang tepat. Opsi `Network` menghubungkan kontainer ke jaringan internal `forgejo` yang telah dibuat. Dua baris `PublishPort` memetakan port `3000` host ke port `3000` kontainer untuk antarmuka web Forgejo, serta port `222` host ke port `22` kontainer untuk layanan SSH internal Forgejo. `Volume` memasang volume persisten `forgejo-data` ke direktori `/data` di dalam kontainer, tempat Forgejo menyimpan seluruh repositori dan basis datanya. Di bagian `[Service]`, pengaturan `Restart=always` memastikan kontainer otomatis dijalankan ulang jika terjadi kegagalan, sementara `WantedBy=multi-user.target` pada bagian `[Install]` membuat layanan ini ikut menyala saat sistem mencapai mode multi‑user sewaktu booting.

Setelah semua berkas siap, muat ulang konfigurasi systemd dengan `sudo systemctl daemon-reload` agar unit yang dihasilkan dari berkas Quadlet dikenali, lalu hidupkan kontainer menggunakan `sudo systemctl start forgejo`. Podman akan mengunduh image, menghubungkan jaringan dan volume, lalu menjalankan kontainer di latar belakang. Anda dapat memantau statusnya kapan saja dengan perintah `systemctl status forgejo`.

Buka peramban di komputer lokal dan arahkan ke `http://10.64.142.206:3000`. Halaman instalasi Forgejo akan menyambut Anda. Isi formulir yang muncul dengan pengaturan berikut: pilih **Database Type** `SQLite3` karena basis data berbasis berkas ini sangat ringan dan tidak memerlukan instalasi tambahan, cocok untuk server kecil. Pada **Server Domain**, masukkan alamat IP `10.64.142.206` yang akan digunakan sebagai alamat kloning repositori. Untuk **SSH Port**, isikan `222` sesuai pemetaan port yang telah ditentukan. Terakhir, tentukan nama pengguna, kata sandi, dan alamat surel untuk akun administrator. Klik **Install Forgejo**, tunggu beberapa detik, lalu masuk dengan akun administrator yang baru dibuat.

Agar dapat berinteraksi dengan server tanpa terus-menerus memasukkan kata sandi, daftarkan kunci publik SSH dari komputer lokal Anda ke Forgejo. Di terminal lokal, buat pasangan kunci ED25519—algoritma modern yang aman—dengan perintah `ssh-keygen -t ed25519` (lewati jika sudah ada), kemudian tampilkan kunci publiknya melalui `cat ~/.ssh/id_ed25519.pub`. Salin seluruh isi yang muncul, dimulai dari `ssh-ed25519`. Pada antarmuka web Forgejo, buka **Settings > SSH / GPG Keys**, tambahkan kunci baru dengan nama pengenal misalnya “laptop”, tempelkan kunci publik yang disalin, lalu simpan. Uji koneksi dengan `ssh -T git@10.64.142.206 -p 222` dan ketik `yes` saat diminta konfirmasi sidik jari server; pesan balasan yang menampilkan nama pengguna Anda menandakan koneksi telah berhasil.

Sekarang buat repositori kosong melalui antarmuka web Forgejo, misalnya dengan nama `backend`. Catat URL SSH yang ditampilkan, yaitu `ssh://git@10.64.142.206:222/<username>/backend.git` (ganti `<username>` dengan nama administrator Anda, contoh `wildanfq`). Di terminal lokal, jalankan serangkaian perintah secara berurutan untuk mengunggah kode perdana. Buat direktori proyek baru dengan `mkdir first` dan masuk ke dalamnya dengan `cd first`. Inisialisasi repositori Git lokal menggunakan `git init`, lalu ciptakan berkas `README.md` kosong melalui `touch README.md`. Buat cabang bernama `main` dan jadikan aktif dengan `git checkout -b main`. Tambahkan `README.md` ke area stage menggunakan `git add README.md`, kemudian rekam perubahan tersebut dengan komit pertama melalui `git commit -m "first commit"`. Daftarkan URL remote server sebagai `origin` dengan perintah `git remote add origin ssh://git@10.64.142.206:222/wildanfq/backend.git`, dan unggah cabang `main` ke server sambil menetapkan pelacakan dengan `git push -u origin main`. Setelah push berhasil, segarkan halaman repositori di Forgejo; berkas `README.md` akan terlihat, menandakan bahwa kode Anda telah tersimpan dengan aman di server.

Ketika versi baru Forgejo tersedia, misalnya dari versi `14` ke `15`, pembaruan dapat dilakukan dengan sangat mudah tanpa memengaruhi data repositori yang berada di volume. Edit kembali berkas kontainer dengan `sudo nano /etc/containers/systemd/forgejo.container`, lalu ubah baris `Image=codeberg.org/forgejo/forgejo:14` menjadi `Image=codeberg.org/forgejo/forgejo:15`. Simpan perubahan, kemudian muat ulang systemd dengan `sudo systemctl daemon-reload`, tarik image versi terbaru menggunakan `sudo podman pull codeberg.org/forgejo/forgejo:15`, dan mulai ulang layanan dengan `sudo systemctl restart forgejo`. Forgejo akan berhenti sejenak, menjalankan migrasi basis data secara otomatis, dan kembali menyala dengan versi yang lebih baru—semuanya tanpa menyentuh data yang telah tersimpan di volume persisten.
